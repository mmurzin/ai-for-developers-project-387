## Сценарии

### 1. Владелец: от создания типа встречи до записи в списке

1. Владелец открывает страницу управления и создаёт тип встречи — указывает название, описание и длительность (например, «Консультация», 30 минут).
2. Новый тип встречи появляется в публичном списке — гости могут записываться по нему.
3. Гость бронирует свободный слот по этому типу (сценарий 2) — встреча сохраняется в базе.
4. В списке предстоящих встреч владельца появляется запись: тип встречи, дата и время, имя и email гостя.

### 2. Гость: запись на звонок

1. Гость заходит на публичную страницу без регистрации и выбирает тип встречи.
2. Открывается календарь на ближайшие 14 дней. Гость выбирает день и видит свободные слоты — слот длится столько, сколько выбранный тип встречи.
3. Гость выбирает свободный слот, указывает имя и email и подтверждает запись.
4. Слот становится занятым: это же время больше нельзя забронировать, даже другим типом встречи. Встреча появляется в списке владельца.

## Деплой

Приложение публикуется одним Docker-образом: multi-stage-сборка (фронт → статический бинарь Go с embed-фронтом → `distroless/static:nonroot`). Платформа передаёт порт через переменную окружения `PORT`, healthcheck — `/health`.

### Docker

```bash
mise run docker-build     # docker build -t call-calendar-387 .
docker run --rm -p 8080:8080 call-calendar-387   # http://localhost:8080/health
```

Порт задаётся через `PORT` (по умолчанию 8080), файл SQLite — через `DB_PATH` (в образе `/data/calls.db`).

### Подключение MCP-сервера Render

Управление деплоем идёт через [Render MCP](https://render.com/docs/mcp-server) из конфигурации проекта (`opencode.json`), без секретов в репозитории:

```json
"render": {
  "type": "remote",
  "url": "https://mcp.render.com/mcp",
  "codemode": false,
  "headers": {
    "Authorization": "Bearer {env:RENDER_API_KEY}"
  }
}
```

Аутентификация — API-ключом Render (OAuth-сервер Render не поддерживает dynamic client registration, поэтому ключ надёжнее). Ключ живёт только в окружении оператора:

```bash
# dashboard.render.com → Account Settings → API Keys → Create API Key
export RENDER_API_KEY=rnd_...
opencode mcp list    # должно показать: ✓ render connected
```

Сервис `call-calendar-387` собирается из репозитория `mmurzin/ai-for-developers-project-387` (ветка `main`) по Dockerfile и обновляется автоматически на каждый пуш. Публичный URL назначает Render.

### Ограничение хранения данных

Демо-стенд работает с **эфемерным хранилищем**: SQLite-файл живёт в файловой системе контейнера и пропадает при каждом передеплое или рестарте — Записи не переживают обновление сервиса. Персистентность (том/диск платформы) сознательно не подключена. Чтобы стенд после вайпа не требовал ручной настройки, при старте на пустой базе сервер сам создаёт два дефолтных Типа звонка (`intro` — Интро-звонок, 15 минут; `consult` — Консультация, 30 минут), см. #26; непустая база не трогается.

Free-инстанс Render засыпает после ~15 минут без трафика: первый запрос после сна может ждать 30–60 секунд (cold start) — это не ошибка, ссылка живая.
