# Эфемерное хранилище демо-стенда Render

Демо-стенд деплоится на Render (free) из Dockerfile; SQLite-файл живёт в файловой системе контейнера, которую платформа пересоздаёт при каждом деплое и рестарте. Решено сознательно не подключать том: это демонстрация, а не прод-инстанс — сценарий проверки не требует персистентности между деплоями, а Render Disk — платная опция и лишняя инфраструктура для учебного проекта. ADR-0001 остаётся в силе для локальных запусков; ограничение зафиксировано в README («Ограничение хранения данных»).

## Considered Options

- Render Disk (том): персистентность, но платно и избыточно для демо-стенда.
- Эфемерный контейнерный файл (выбран): бесплатно и просто; данные стираются при передеплое.

## Consequences

- Передеплой или рестарт стирает Типы звонков и Записи стенда.
- После вайпа сервер сам восстанавливает дефолтные Типы звонка посевом при старте (seed-if-empty, #26) — ручная пересборка стенда не нужна; Записи остаются эфемерными.
- Персистентность включается подключением тома без правок кода: `DB_PATH` указывает на смонтированный каталог.
