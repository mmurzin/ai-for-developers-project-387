# SQLite как хранилище записей и доступности

Бэкенд до этого момента обходился stdlib без хранилища; для интервалов доступности, Записей и сессий владельца нужна персистентность. Выбран SQLite с pure-Go драйвером (без cgo): один файл, транзакции, бинаррь остаётся самодостаточным (в духе go:embed). Это первая внешняя Go-зависимость проекта — осознанно: in-memory обесценивал горизонт бронирования и историю отмен, Postgres требовал инфраструктуры, которой нет (деплоя на VPS ещё нет).

## Considered Options

- In-memory: ноль зависимостей, но данные исчезают при рестарте — горизонт 14 дней и отмена Записей бессмысленны без персистентности.
- PostgreSQL: внешний сервис; деплой и VPS отсутствуют, тянул бы инфраструктуру впрок.
- SQLite (pure-Go, например modernc.org/sqlite): выбран.

Дальше по жизни решения: деплой-контекст описан в ADR-0002 — демо-стенд Render работает с эфемерным файлом SQLite (без тома).
